# Дизайн-система «Сферы»

Единый источник правды — CSS-токены в `app/globals.css` и примитивы там же.
Компоненты не изобретают цвета заново: они берут токен. Любая правка палитры
= правка блока `:root` / `.dark`, остальное перекрашивается само.

## Темы

Механика: `localStorage["sfera-theme"]` → класс `.dark` на `<html>` →
перекрываются токены. Переключатель — `components/site/ThemeToggle.tsx`,
анти-FOUC-скрипт — в `app/layout.tsx`.

Правило: **никаких `dark:text-*` / `dark:bg-*` с палитрой в компонентах.**
Тема живёт в токенах, класс `dark:` остаётся только для эффектов, у которых нет
светлого аналога (свечение цифр при наведении, `dark:group-hover:*`).

Правило симметричное: **в публичном коде нет и литералов палитры** —
`bg-white/3`, `text-violet-600`, `stroke="white"`, `bg-black/50`. Такой класс не
переворачивается темой, то есть это либо случайная инверсия во второй теме, либо
поверхность, которая притворяется темой. Нужна «не тематизируемая» белая/чёрная
подложка — заводи токен с фиксированным значением и класс-примитив
(`--paper` → `.paper-plate`, `--photo-film` → `.play-badge`), а не литерал в
разметке. Разница между двумя случаями принципиальная: *тематическая*
поверхность (`bg-brand-warm/10`) обязана меняться, *кадровая* (`--frost-*`,
`--plate-*-ink`, `--photo-*`) — обязана НЕ меняться, потому что фото в обеих
темах одно и то же.

Скан: `pptr-check/no-hardcode-check.js` вычитывает `components/site` и
публичные маршруты `app/` (админка и лаборатории исключены) и падает на любом
литерале палитры или цвете в атрибуте/стиле. Тени вида
`shadow-[..._rgba(0,0,0,.55)]` не считаются: чёрная тень с разной плотностью —
это не палитра, её проверяют пробы контраста.

## Каркас и подписи кнопок

- `.container-max` полей **не даёт**: он для секций, у которых поля уже есть в
  `.section-padding`. Страница целиком (`/programs/…`, `/news/…`, `/raspisanie`,
  `/reviews`, `/gallery`) оборачивается в `.container-page` — иначе на экранах
  уже 1280px контент встал вплотную к краю, а кнопки в узкой колонке сжимались
  и переносились.
- Подпись кнопки не переносится (`.btn-cta`/`.btn-outline` держат `nowrap`);
  если места не хватает — **переносится ряд кнопок** (`flex-wrap`), а не текст
  внутри кнопки.
- Картинка в расписании (`schedule[i].image`) грузится в админке кнопкой
  «Загрузить файл» и лежит под таблицей группы ссылкой на полноразмерный лист:
  на экране есть, в `@media print` скрыта — печатают сам файл. У любого поля с
  картинкой обязаны быть оба контроля: выбор из медиатеки **и** загрузка с ПК
  (`pickBtn` в `app/admin/page.tsx`), только выбор — половина функции.
- Телефон в кнопке — глиф `Phone` с `aria-label` и `title` с настоящим номером
  (номер виден в шапке, контактах и подвале). Цельный номер внутри `h-12 px-7`
  не помещался и рвался по цифрам: «+7 (928) 434-91-» / «08».

## Печать — это отдельный шаблон, а не экранная страница

Печатать то, что на экране, нельзя: стеклянные карточки, 5xl-заголовки и
экранная сетка разворачивали расписание на две-три страницы, а в бумагу лезли
шапка, подвал и кнопки.

- Для бумаги есть **`components/site/SchedulePrint.tsx`** — компактный бланк
  A4: шапка с названием студии, адресом и телефоном, далее по группе — сетка
  «дни колонками», уроки отсортированы по времени, дни по порядку недели,
  внизу строка «забирать HH:MM» и примечание с телефоном.
- Экранный блок страницы прячется одним `print:hidden` на контейнере
  (`app/raspisanie/page.tsx`), бланк показывается правилом
  `.schedule-sheet { display: none }` → `display: block` внутри `@media print`.
- Поля листа задаёт `@page { size: A4 portrait; margin: 12mm 12mm 10mm }`:
  без этого Chrome подставляет свои 12.7мм и высота листа внезапно оказывается
  меньше контента.
- На бланке нет ни стекла, ни теней, ни фирменных цветов: только чёрный текст
  и волосяные линии сетки. Типографика 8.5pt, при >34 уроках включается
  `.schedule-sheet--dense` — страховка от роста данных.
- **Fit доказывается PDF'ом, а не eyeball:** `pptr-check/print-sheet-check.js`
  вызывает `page.pdf({ preferCSSPageSize: true })` и считает объекты
  `/Type /Page` в файле — их должен быть ровно один. Chrome отдаёт PDF как
  `Uint8Array`, у которого нет `toString("latin1")` (байты становятся
  «37,80,68…»), поэтому в щупе сначала `Buffer.from(...)`, иначе счётчик
  молча возвращает 0 страниц.

## Проба ховера: ловушка плавной прокрутки

`page.$(...).hover()` на этом сайте **не даёт `:hover`** у элементов в глубине
длинной страницы: у `html` стоит `scroll-behavior: smooth`, Puppeteer
прокручивает и тут же ставит курсор в координаты, вычисленные до прокрутки.
Признак — `elementFromPoint` показывает нужную кнопку, а `el.matches(":hover")`
возвращает `false`. Как надо: `scrollIntoView({behavior:"instant"})`, дождаться
покоя, пересчитать `getBoundingClientRect()` и вести мышь в свежий центр,
 polled до `:hover === true` (см. `redesign-audit.js`, блок ховера).

Вторая ловушка того же блока: «улёт» стрелки сделан одноразовым
`@keyframes btn-arrow-nudge`, поэтому читать надо `animationName` в момент
наведения (и `none` без курсора), а не `transform` — после окончания анимации
computed `transform` снова `none`, и наивная проверка вечно падает.

## Имя файла в галерее

В списке галереи у каждой строки показаны **номер позиции и имя файла** — иначе
свежезагруженный снимок приходится искать «на глаз». Номер честный: админский
`GET /api/admin/photos` и сайт (`lib/content.ts`) выбирают строки одним и тем же
порядком — `sort_order ASC, id ASC`, — поэтому «позиция 37» в админке есть
«37-й кадр» на сайте: на главной это лента (право = конец), на `/gallery` —
сетка вниз.

Имя в URL строит `lib/photo-key.ts`: кириллицу транслитерируем
(«Отчёт о празднике.jpg» → `Otchyot_o_prazdnike.JPG`), всё остальное режем до
ASCII, расширение сохраняем с точкой. Причина не в красоте: Supabase Storage
отвергает ключи с кириллицей ответом `400 InvalidKey` (замерен
`storage-unicode-key.js`), а прежний санитар без транслитерации оставлял от
русского имени `_.jpg` — опознать файл было нельзя. Расширение в ключе носят
`isVideoSrc` и `IMAGE_EXT_RE`: без точки видео переставало быть видео.

## Админка: обещать только то, что случилось

Долгие месяцы админка стреляла мутации «в ответ»: `await fetch(...)` без
проверки статуса, и интерфейс сразу правил список. Если сессия истекла (cookie
живёт 7 дней) или сервер ответил 500, получалось враньё: карточка исчезала,
зелёный тост говорил «Удалено», а в базе файл оставался — счётчик на сайте не
двигался, после перезагрузки снимок возвращался. У массовой загрузки был свой
вариант той же болезни: итоги читались из `uploadQueue` — state-массива, который
внутри цикла ещё не обновился, — и «Загружено 8 файлов ✓» показывалось даже
когда не загрузился ни один.

Правила:

- мутации идут через `mutate(url, init)` — он бросает `Error` с текстом с сервера
  и отдельно расшифровывает 401 как «сессия истекла — войдите заново»;
- интерфейс меняется **после** успешного ответа, а при провале — откатывается
  (`toggleNewsVisible`, `setEnrollmentStatus`) или перечитывается с сервера
  (`deletePhoto`), чтобы список не расходился с базой;
- число загруженного/остального считается по фактическим результатам, а не по
  задуманным (`uploadSingle` возвращает `true | текст ошибки`);
- тост различает успех и провал: `data-admin-msg="ok" | "bad"`, провал — цветом
  ошибки и живёт дольше (6 с против 2,5 с). Раньше и «Ошибка», и «Сохранено ✓»
  были одним зелёным.

В шапке вкладки «Галерея» показан итог — `data-gallery-total` — и он обязан
равняться количеству строк в базе и числу, которое считает сайт.

## Контакты: один источник и видимость везде

Ссылки на мессенджеры берутся только из `siteConfig` (`vkUrl`, `maxUrl`,
`phoneHref`) — пустое значение значит «кнопки нет», а не «битая кнопка». MAX
живёт в семи местах: мобильное меню шапки, мобильная панель, строка и кнопка в
секции «Контакты», блок призыва, форма записи, подвал, страница направления; плюс
`sameAs` в JSON-LD. Проверка — `max-contact-check.js`: она же следит, что все
ссылки уходят `target="_blank"` с `rel="noopener"`, и что панель из четырёх
кнопок (звонок, VK, MAX, запись) не обрезает подписи на 390px.

Две ловушки, из-за которых «везде» проверяется машиной, а не глазами:
мобильная панель рендерится только после первого экрана (`if (!visible) return
null`), а кнопка в шапке лежит не внутри `<header>`, а в выезжающем слое меню —
наивный `header.querySelector` даёт ложное «нет».

Раньше в JSON-LD организации были вписаны вручную телефон-заглушка
(+7 918 345-67-89) и несуществующая группа `vk.com/sfera_gk` — поисковики
отдавали их как реквизиты. Теперь `telephone` и `sameAs` приходят из
`data/site.ts`; дефолты там же, откуда стартует админка.

## Правка в админке обязана доходить до всех страниц

Данные контент берёт из Supabase поверх статических дефолтов (`lib/content.ts`).
Половина публичных страниц — `force-dynamic` (`/`, `/gallery`, `/raspisanie`):
они читают базу на каждый запрос. Остальные (`/programs/[id]`, `/news`,
`/reviews`, `/privacy`) — статические, попадают в Full Route Cache на сборке и
обновляются только когда их явно инвалидировать.

Раньше каждая мутация в админке звала `revalidatePath("/")` — это ровно один
маршрут, а не вся иерархия. Поэтому «в админке поменял, на сайте нет» было
справедливым описанием системы: главная обновлялась, страница направления,
отзывы и новости висели протухшими до ближайшей пересборки. Теперь все
админские записи зовут `revalidatePath("/", "layout")` — область `layout`
закрывает `/` и всё, что вложенное.

Второе наблюдение, пойманное на проде: после деплоя `/` продолжал отдавать HTML
прошлой сборки (`x-vercel-cache: MISS`, `age: 0` — то есть не CDN, а сама
функция), хотя `/api/admin/settings` того же инстанса уже видел новую базу.
Лечится тем же сбросом — любое сохранение в админке. Проверено: до — ноль
ссылок на MAX в HTML, после одного сохранения — пять.

## Контраст — обязательный порог


WCAG AA, считается по пикселям, а «на глаз» не проверяется никогда:

- обычный текст ≥ **4.5:1**, крупный (≥24px или ≥18.66px bold) ≥ **3:1**;
- индикатор фокуса ≥ 3:1 к соседним цветам;
- полупрозрачный текст (`text-on-scrim/70`) считается **в смеси с подложкой**,
  70% белого на сером — это ~4:1, а не 12:1;
- текст поверх фотографии лежит на светлой подложке (`.glass-frost` /
  `.paper-plate`), а не на фото и не на тёмной плёнке; читаемость мерится
  **по пикселям реального кадра** — `plate-contrast.js`, а не по `bgOf`,
  который фотографию не видит;
- подложки, принадлежащие кадру, в тёмной теме НЕ переворачиваются, и текст на
  них обязан быть фиксированным (`--frost-ink`, `--plate-*-ink`). Обычный
  `--brand-*-ink` в тёмной теме светлеет: на белой пилюле это давало 1.81:1.

## Движение

Правило: **отношение к движению не должно лишать контента.** `fineMotion`
(`prefers-reduced-motion: no-preference` в `Hero.tsx`) гасит наклоны, параллакс и
затухание при смене кадра, но сами кадры, текст и ссылки остаются доступными.
Плюс у пользователя всегда есть явная пауза всего движущегося — рубильник в
шапке (см. «Кадр героя»).

- Хиро: кадр с фото наклоняется за курсором (`rotateX/rotateY` ±7°,
  `transformPerspective: 1200`), а две карточки-факта висят **снаружи углов** и
  едут против наклона с `translateZ` 46 / 62 px — на `preserve-3d` родителе.
  Без угловых слоёв наклон почти не читается: объём дают именно они.
- «Дыхание» кадра (`.hero-breathe`) — отдельная CSS-анимация: на framer-ключевых
  кадрах с `repeat: Infinity` доходило до 1.05 и останавливалось.
- Бегущая строка под `reduce` не останавливается, а едет медленнее
  (`.animate-marquee` 36s → 90s, `.belt` — ×2.6); полностью — кнопкой паузы.

## Кадр героя

Снимки из `heroContent.images` меняются сами каждые 7 секунд кроссфейдом внутри
кадра с **неизменным** соотношением сторон (`aspect-square`, с `sm` —
`aspect-[5/4]`, `object-cover`): ориентация снимка разрешается обрезкой, а не
размером блока.

Раньше рамка подстраивалась под отношение сторон текущего снимка (кламп
0.85…1.5), и альбомный кадр с книжным давали разную высоту героя — вместе с
посадкой угловых плашек. Жёсткий кадр это убирает; цена — с альбомного фото
срезаются края, с книжного верх и низ, и `hero-breathe` (scale 1.05) съедает
ещё ~2,5% с каждой стороны.

На кадре управления нет вообще: ни точек, ни паузы. Авто-смена при этом живёт —
её право на это даёт рубильник «пауза анимаций» в шапке (`MotionToggle`,
`lib/motion.ts`): WCAG 2.2.2 требует механизм остановки движущегося содержимого,
а приём G186 разрешает этому механизму быть в любом месте страницы — лишь бы он
был доступен с клавиатуры и не оказался ниже движущегося блока в порядке
табуляции. Шапка — как раз начало.

Рубильник ставит на паузу всё, что крутится само: смену фото (таймер в `Hero`
подписан на то же состояние) и keyframes-анимации (`.animate-marquee`, `.belt`,
`.hero-breathe`, `.blob-drift` — через `animation-play-state`, а не через
`animation: none`, чтобы кадр ленты не прыгал в начало). Выбор пишется в
`localStorage["sfera-motion"]` и применяется инлайн-скриптом до гидрации, как и
тема; состояние — атрибут `data-motion="paused"` на `<html>`, единственный
источник истины и для CSS, и для React.

И отдельно `prefers-reduced-motion: reduce`: смена кадров остаётся, но без
кроссфейда (меняется содержимое, а не положение), «дыхание» и дрейф пятен
гаснут, лента едет медленнее.

Мерить это надо с `emulateMediaFeatures([{ prefers-reduced-motion:
no-preference }])`: в headless Chrome по умолчанию стоит `reduce`, там наклон
не включается никогда, и «transform: none» в такой прогон — баг измерения, а не
сайта. И наоборот: если «работало раньше, а теперь нет» — сначала
`hero-frame-check.js` в обоих режимах, потом правки.

```bash
npx next build && npx next start -p 3000
node ../pptr-check/redesign-audit.js    # 120 проверок: 12 маршрутов × 2 темы (+ живые id новостей и slug'и)

node ../pptr-check/hero-frame-check.js  # кадр: фиксированный размер, обрезка, смена фото и рубильник паузы
node ../pptr-check/plate-contrast.js          # читаемость текста карточек-фактов на пикселях реального кадра (2 темы × 3 ширины, ротация на паузе)
node ../pptr-check/print-sheet-check.js       # бланк расписания: страницы настоящего PDF, полнота контента, стресс ×4 группы

node ../pptr-check/alpha-token-check.js       # модификатор /NN на токенах действительно даёт альфу, а не сплошной цвет
node ../pptr-check/schedule-volume.js         # сколько данных в расписании (группы/дни/уроки) — входные данные для бланка
node ../pptr-check/cta-wrap-check.js        # CTA: переносы подписей, вылезание за край, поля от края, имя у кнопки-глифа
node ../pptr-check/admin-schedule-upload.js # в админке у каждого пикера есть пара «загрузить файл» (только чтение)
```

Аудит считает подложку текста честным Porter–Duff по всей цепочке предков
(стопы `linear-gradient` — слоем на своём месте, полупрозрачный текст — в смеси
с подложкой), поэтому «1.09:1» из непроверенной модели — не повод править
вёрстку: сначала `pixel-oracle.js`. Любой из аудитов можно прогнать по боевому
домену: `DSH_BASE=https://gksfera.vercel.app`.
